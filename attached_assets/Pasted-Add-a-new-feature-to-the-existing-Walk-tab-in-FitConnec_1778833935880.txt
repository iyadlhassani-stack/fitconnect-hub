Add a new feature to the existing Walk tab in FitConnect: route generation that prioritizes passing through scenic Points of Interest (POIs) like parks, monuments, squares, and viewpoints.

## OVERVIEW

When a user generates a walking route, the app should:
1. Search for interesting POIs along/near the planned route
2. Try to incorporate them as waypoints in the generated route
3. Only do this if it doesn't significantly deviate from the user's goal (+/-10%)
4. Display the POIs the user will encounter with photos before they start

## API REQUIREMENTS

### Overpass API (free, OpenStreetMap)
For finding POIs:
- Endpoint: https://overpass-api.de/api/interpreter
- No API key needed
- POST request with Overpass QL query

POI types to fetch:
- leisure=park (parks)
- historic=monument or historic=memorial (monuments and memorials)
- amenity=square or place=square (public squares)
- tourism=viewpoint (scenic viewpoints)
- amenity=fountain (fountains)

Query example (around route bounding box):
[out:json][timeout:25];
(
  node["leisure"="park"](BBOX);
  node["historic"~"monument|memorial"](BBOX);
  node["amenity"="square"](BBOX);
  node["place"="square"](BBOX);
  node["tourism"="viewpoint"](BBOX);
  node["amenity"="fountain"](BBOX);
  way["leisure"="park"](BBOX);
);
out center;

Where BBOX is calculated from the route's bounding box, expanded by ~500m on each side.

### Wikipedia API (free) - for photos and descriptions
For each POI with a name:
1. Search Wikipedia: https://en.wikipedia.org/w/api.php?action=query&format=json&prop=pageimages|extracts&exintro&explaintext&exsentences=2&pithumbsize=400&titles=POI_NAME&origin=*
2. Also try French Wikipedia if user language is French: https://fr.wikipedia.org/w/api.php with same params
3. Extract:
   - thumbnail.source (photo URL)
   - extract (short description)
4. If no Wikipedia page found, use default icon based on POI type

Default icons (use Lucide React icons):
- Park: TreePine icon, green
- Monument: Landmark icon, brown
- Square: Building icon, gray
- Viewpoint: Mountain icon, blue
- Fountain: Droplet icon, cyan

## ROUTE GENERATION LOGIC

### Algorithm
1. Generate the BASE route first (Loop or A to B) without POI consideration
2. Get the route's bounding box (min/max lat/lng)
3. Query Overpass API for POIs within bbox expanded by 500m
4. Filter POIs by user-selected categories
5. Score each POI:
   - Distance from route line: closer = higher score
   - POI importance (parks > monuments > squares > viewpoints > fountains)
   - Has Wikipedia photo: +bonus score
6. Pick top 3-5 POIs to try incorporating
7. Generate alternate route passing through these POIs as waypoints
8. Check if alternate route is within +/-10% of user's goal:
   - If YES: use alternate route, return POIs to display
   - If NO: remove the least important POI and retry
   - If after 3 retries still no fit: return base route + show POIs as "nearby" without forcing detour

### Code structure
Add new service file: services/poiService.js with functions:
- searchPOIs(bbox, categories) -> returns array of POIs
- enrichPOIWithWikipedia(poi, language) -> returns POI with photo and description
- scorePOIs(pois, routeGeometry) -> returns sorted POIs
- selectOptimalPOIs(pois, route, goalDistance) -> returns up to 5 POIs that fit

## EDGE CASES

1. POI has no Wikipedia entry:
   - Show default icon for the POI type
   - Description: "A nice spot to discover"

2. Wikipedia API rate limit hit:
   - Cache photos in localStorage for already-fetched POIs
   - Gracefully fallback to default icons

3. No POIs in the area (rural/suburban):
   - Show note: "No scenic spots found nearby. Try a larger goal distance."

4. POIs would make route too long:
   - Strip the lowest-scored POI
   - Retry until fits

5. User disables ALL POI categories:
   - Skip the entire POI logic
   - Generate route as before
