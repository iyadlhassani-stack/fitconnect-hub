## NEW MODE STRUCTURE - 3 MODES ONLY

Remove the existing mode "A to B + Calories" (it was redundant with A to B + goal).
Keep and refine these 3 modes:

### Mode 1: Loop
- User inputs: 1 starting point
- User inputs: goal type (Calories OR Minutes OR Distance)
- User inputs: goal value
- User inputs: walking pace (Slow/Normal/Fast)
- App generates: a circular route that returns to the starting point

### Mode 2: A to B (intelligent)
- User inputs: starting point
- User inputs: end point
- User inputs: walking pace (Slow/Normal/Fast)
- Goal is OPTIONAL (not required):
  - If goal NOT filled OR goal less than direct route: generate direct shortest route
  - If goal greater than direct route: generate route with detour to reach the goal
  - If goal impossible (e.g., 100 kcal requested but direct route requires 350 kcal minimum): show clear error message, do NOT generate a fake route

### Mode 3: Custom Route
- User inputs: starting point
- User inputs: 0 to many intermediate stops with + Add Stop and X delete buttons
- User inputs: final destination
- User inputs: walking pace
- NO goal field in this mode (user chose the path)
- App generates: route passing through all waypoints in order
- Display: actual stats of the generated route (distance, duration, calories)

## ALGORITHM - COMPLETE REWRITE

The current calculation logic is fundamentally broken. Rewrite it with this clean structure.

### Single source of truth: services/walkService.js

Create or rewrite this file with these pure functions:

MET_VALUES = { slow: 3.0, normal: 3.5, fast: 4.5 }
SPEED_VALUES = { slow: 4, normal: 5, fast: 6 } (km/h)

Functions to implement:
- durationFromCalories(calories, weight_kg, pace) returns minutes
  formula: (calories / (MET * weight_kg)) * 60
- distanceFromDuration(duration_min, pace) returns km
  formula: (duration_min / 60) * speed
- distanceFromCalories(calories, weight_kg, pace) returns km
  combines the two above
- caloriesFromDistance(distance_km, weight_kg, pace) returns kcal
  formula: MET * weight_kg * (duration_min / 60)
- durationFromDistance(distance_km, pace) returns minutes
  formula: (distance_km / speed) * 60
- goalToTargetDistance(goalType, goalValue, weight_kg, pace) returns km
  switch on goalType
- computeRouteStats(actualDistance_km, weight_kg, pace) returns { distance_km, duration_min, calories, pace }

### CRITICAL RULES

1. After OpenRouteService returns a route, ALWAYS use computeRouteStats(actualDistance, userWeight, pace) to display stats. Do NOT use the duration/calories returned by OpenRouteService (they are not personalized).

2. The displayed calories MUST be consistent with the displayed distance and pace. For the same distance across paces, kcal should vary by less than 15% (not 50%+ like currently).

3. The DURATION must change clearly with pace:
   - 5 km at slow pace = approximately 75 minutes
   - 5 km at normal pace = approximately 60 minutes
   - 5 km at fast pace = approximately 50 minutes

## ROUTE GENERATION LOGIC PER MODE

### Mode 1: Loop
1. Convert goal to target distance: targetKm = goalToTargetDistance(...)
2. Validate: if targetKm < 0.5 km, show error "Distance too short. Minimum is 500m"
3. Validate: if targetKm > 50 km, show error "Distance too long. Maximum is 50km"
4. Call OpenRouteService /v2/directions/foot-walking with options.round_trip:
   length: targetKm * 1000 meters, points: 5, seed: random
5. Compute stats from the ACTUAL distance returned by ORS using computeRouteStats()
6. Display: distance, duration, calories

### Mode 2: A to B (intelligent)
1. Generate the direct A to B route first via OpenRouteService
2. Get direct distance: directKm
3. Compute stats for direct route: directStats = computeRouteStats(directKm, weight, pace)

4. If user did NOT fill a goal:
   - Use the direct route as-is
   - Display stats of direct route
   - Label: "Direct route"

5. If user filled a goal:
   - Compute target distance: targetKm = goalToTargetDistance(...)
   - If targetKm < directKm (impossible):
     - Show RED error card: "Goal impossible. The direct walk from A to B already requires X km / Y min / Z kcal."
     - Show button: "Use direct route anyway" generates direct route with its real stats
     - Show button: "Adjust goal" scrolls to goal input
     - Do NOT generate a fake route
   - If targetKm greater than or equal to directKm:
     - Calculate detour needed: detourKm = targetKm - directKm
     - Find a waypoint to add the detour:
       - Compute midpoint M of A-B
       - Add perpendicular offset from M of detourKm / 2
       - Try generating A to waypoint to B
       - Check if actual distance is within 10% of target
       - If not, try different perpendicular offset
       - Maximum 3 attempts
     - If all attempts fail, show YELLOW warning: "Closest match: X km. Your goal was Y km."
     - Compute stats from ACTUAL distance returned

### Mode 3: Custom Route
1. Validate: at least starting and ending points provided
2. Call OpenRouteService with all waypoints in order
3. If route generation fails:
   - Show error: "Could not connect these points by walking."
4. Compute stats from ACTUAL distance using computeRouteStats()
5. Display: distance, duration, calories
6. Show note: "Custom path. Stats calculated based on your pace."
